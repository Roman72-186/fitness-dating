# Правило: сохранение анкеты очищает старую историю

Дата: 2026-06-29

## Проблема

Если пользователь удалил себя в WATBOT, затем создал новую анкету с тем же `telegram_id`, приложение раньше воспринимало это как обычный `upsert`.

Из-за этого в базе оставались старые связи:

- `skip` в `profile_actions`;
- исходящие лайки;
- входящие лайки;
- мэтчи.

Результат: новая анкета уже имела старую историю, лента могла быть пустой, а старые лайки продолжали отображаться.

## Новое правило

Любое сохранение анкеты считается полной заменой текущего состояния анкеты.

Перед сохранением анкеты нужно очистить всю историю пользователя в обе стороны:

- `profile_actions.viewer_profile_id = userId`;
- `profile_actions.target_profile_id = userId`;
- `matches.user_a_id = userId`;
- `matches.user_b_id = userId`.

После очистки сохраняется актуальная анкета.

## Где применяется

- `POST /api/bot/register-profile`;
- `POST /api/profile`;
- `PUT /api/profile`.

## Где не применяется автоматически

`POST /api/admin/sync-from-watbot` не должен массово чистить историю всем пользователям при обычном админском импорте. Иначе один bulk sync может обнулить всю историю лайков, пропусков и мэтчей.

Если понадобится массовая пересборка базы, это должно быть отдельное явное админское действие с подтверждением и бэкапом.

## Проверка

1. У пользователя есть старые `profile_actions` и `matches`.
2. Пользователь сохраняет анкету через `/api/bot/register-profile`, `POST /api/profile` или `PUT /api/profile`.
3. Старые `profile_actions` и `matches` пользователя удалены в обе стороны.
4. Новая анкета сохранена.
5. `/api/feed`, `/api/likes` и `/api/matches` не показывают старую историю.
